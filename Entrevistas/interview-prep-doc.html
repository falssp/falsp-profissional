Perguntas e respostas modelo

Como você recomendaria ao cliente quais ferramentas do GMP utilizar?Contexto ▼

A recomendação parte de três eixos:

1. Objetivo de negócio — mensuração cross-channel → CM360 (quase sempre obrigatório); automação de lances + dados first-party → DV360; eficiência em search multi-conta → SA360.

2. Maturidade operacional — time interno capacitado: stack completo; sem time: CM360 como base de mensuração, DSP operado pela Daxgo; budget pequeno: CM360 standalone resolve.

3. Ecossistema de mídia — só Google: Google Ads + CM360; mídia aberta (PMPs, deals, publishers diretos): DV360 se justifica; multi-agência ou multi-país: CM360 como camada de governança agnóstica.

💡 Frase de fechamento
"A recomendação raramente é 'use tudo'. É qual combinação entrega o melhor retorno sobre o custo de implementação e operação — e essa conta muda para cada cliente."
Como você faria o mapeamento e auditoria de Floodlights com conversões offline?Técnico ▼
1
Inventário Exportar lista completa de Floodlight Activities — nome, tipo (Counter/Sales), formato (GTM/tag direta), status (ativo/sem dados 30d).
2
Validação técnica Tag Diagnostics do CM360 para erros de implementação; verificar Custom Variables (u1, u2...) e deduplication key configurada.
3
Conversões offline Mapear fluxo: evento online gera GCLID → CRM captura → venda offline → upload recorrente via SA360 ou API. Sem GCLID no CRM, a integração não funciona.
4
Entregável Planilha de auditoria com status de cada Floodlight, ação recomendada (manter/pausar/recriar) e prioridade — parceria com time de Dados para automação.
Como estruturar a governança de uma conta GMP do zero para um cliente enterprise?Técnico ▼

Estrutura de contas: espelhar hierarquia entre CM360, DV360 e SA360 — 1 Network/Partner/Manager Account → Advertisers por marca → Campaigns por objetivo. Facilita reporting cross-tool.

Taxonomia: definir padrão antes de criar qualquer elemento: [Marca]_[Objetivo]_[Canal]_[Formato]_[Data]. Documentar e exigir aprovação para desvios.

Permissões: menor privilégio — read-only (cliente), editor (agência), admin (Daxgo/consultor). Auditar a cada trimestre.

Documentação: Floodlight map + runbook de operação com SLAs e processos de aprovação.

Como o Path to Conversion do CM360 apoia decisões de atribuição?Técnico ▼

O P2C mostra a sequência de touchpoints antes da conversão. Cada linha é um caminho único com sua frequência — você vê quais canais aparecem no topo, meio e fundo do funil.

Como usar: calcular o Assisted Conversion Rate de cada canal. Se Display aparece muito no meio do funil mas recebe pouco crédito no modelo last-click → está sendo subfinanciado. Base para migrar para DDA (Data-Driven Attribution) com dados em mãos.

⚠️ Limitação importante
O P2C só captura touchpoints de ads servidos via CM360 — não vê search orgânico, social fora do GMP nem email. Mencionar isso na entrevista demonstra maturidade.
Quando o SA360 se justifica frente ao Google Ads nativo?Avançado ▼

SA360 se justifica quando o cliente tem complexidade que o Google Ads nativo não resolve:

  • Múltiplas engines: Google Ads + Microsoft Advertising (Bing) + Yahoo Japan em uma interface — com métricas comparáveis
  • Smart Bidding cross-conta: lances otimizados considerando o portfólio inteiro, com Floodlight como sinal de conversão unificado
  • Inventory Management: cria e pausa anúncios automaticamente baseado em feed de produto/estoque
  • Exportação para BigQuery via Reporting API — mais granular que o Google Ads nativo

Quando NÃO vale: cliente só com Google Ads, budget pequeno e sem necessidade de automação avançada — o custo de licença não se justifica.

Como você integraria CM360/DV360 com GA4 e BigQuery para visão unificada de performance?Avançado ▼

Arquitetura:

  • Floodlight ↔ GA4: link via "Linked Accounts" no CM360 — conversões Floodlight ficam visíveis como eventos no GA4
  • DV360 ↔ BigQuery: Data Transfer exporta impression_v2, click_v2, activity_v2 em nível de usuário
  • GA4 ↔ BigQuery: export nativo, tabela diária events_YYYYMMDD
  • Unificação: tabela mestre no BigQuery cruzando GCLID/DCLID entre as fontes → Looker Studio ou Power BI com métricas unificadas

Resultado: visão completa do funil — da impressão programática à conversão final, sem depender dos relatórios nativos de cada plataforma.

Como você conduziria o onboarding de um cliente migrando de outro ad server para o CM360?Avançado ▼
1
Discovery (sem. 1–2) Entender setup atual, fluxo de criativos, conversões rastreadas, publishers, dependências (agência, dados, contratos).
2
Setup técnico (sem. 2–4) Criar estrutura CM360, implementar Floodlights, configurar Custom Variables. Rodar os dois ad servers em paralelo por 2–4 semanas para validação.
3
Operação assistida (mês 2) Trafegar primeiras campanhas junto com o time do cliente — não por eles. Treinar em Report Builder e troubleshooting. Estabelecer SLAs.
4
Handoff (mês 3+) Documentar runbook e Floodlight map. Desligar ad server antigo após dados estáveis. Manter check-ins mensais estratégicos.

Seus diferenciais para destacar

  • Experiência em cliente multinacional (Unilever BR) — ambiente de alta complexidade e múltiplas agências, exatamente o que a Daxgo atende

Perguntas para fazer ao entrevistador

Perguntas inteligentes demonstram senioridade e interesse genuíno. Escolha 2–3 — abaixo com contexto para calibrar a pergunta:

  • "Quais são os principais desafios que os clientes Daxgo enfrentam hoje na adoção do GMP — é mais técnico, cultural ou de governança?"
    → Provavelmente as três camadas. Área é nova — espera confirmar isso e mostrar que você sabe navegar contextos de mudança.
  • "Como é a relação entre o consultor Daxgo e o time do Google? Há acesso a suporte técnico dedicado?"
    → Daxgo deve ter canal dedicado Google. Se confirmar, menciona que isso é diferencial frente a agências que dependem do suporte aberto.
  • "Qual é o perfil típico de cliente da Daxgo — agências ou anunciantes diretos? Qual o tamanho médio das contas?"
  • "Como é estruturado o processo de onboarding de um novo consultor — há imersão técnica nas ferramentas antes da alocação em clientes?"
    → Vaga é remota; presença em cliente pode acontecer pontualmente mas não é padrão. Nada foi confirmado ainda — a pergunta em si já mostra maturidade.
  • "Quais são as certificações que a Daxgo espera que o consultor mantenha ativas?"
    → Mínimo esperado: certificações GMP (CM360, DV360, SA360). Abre espaço para você mencionar as que já tem e as que está renovando.
